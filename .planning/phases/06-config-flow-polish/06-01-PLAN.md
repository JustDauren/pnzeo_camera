  **Step-by-step flow changes:**

  1. **Import CONF_CAPABILITIES** from `.const` (add to existing import).

  2. **async_step_user** -- Keep as-is. User chooses "discover" or "manual".

  3. **async_step_discover** -- Keep current logic. On single camera found, set BOTH `self._host = d["ip"]` AND `self._device_id = d["device_id"]`. On multiple cameras, show pick form (already works).

  4. **async_step_pick** -- When user picks a camera, set `self._host` and also `self._device_id` from the matching discovered entry. Then proceed to credentials.

  5. **async_step_manual** -- REWRITE completely. This is the manual UID/IP entry (CONF-02):
     - Show form with `device_id` (required) and `host` (optional, default="")
     - On submit: store `self._device_id = user_input[CONF_DEVICE_ID]`, `self._host = user_input.get(CONF_HOST, "")`
     - If host provided, validate with `check_rtsp(host)`. On failure set `errors["base"] = "cannot_connect"` and re-show form
     - If no host provided (UID-only, cloud relay), proceed directly to credentials
     - Proceed to `async_step_credentials`

  6. **async_step_credentials** -- REWRITE for CONF-03 + CONF-04:
     - Show form with `password` (required) and `rtsp_port` (optional, default=554)
     - NO device_id field here (moved to manual/discovery steps)
     - On submit:
       a. Call `self._verify_pppp_login(self._host, password, self._device_id)` -- returns `True` (ok), `False` (wrong password), `None` (can't connect, allow anyway)
       b. If `False`: `errors["base"] = "invalid_auth"`, re-show form
       c. If `True` or `None`:
          - Set unique_id = `self._device_id` if non-empty, else `self._host.replace(".", "_")`
          - Call `self.async_set_unique_id(unique_id)` + `self._abort_if_unique_id_configured()`
          - Build data dict: `CONF_HOST`, `CONF_USERNAME` (DEFAULT_USERNAME), `CONF_PASSWORD`, `CONF_DEVICE_ID`, `CONF_RTSP_PORT`, and `CONF_CAPABILITIES` (from `self._capabilities` populated during verify)
          - `self.async_create_entry(title=f"PNZEO {self._device_id or self._host}", data=data)`

  7. **_verify_pppp_login** -- ENHANCE for capability capture (CONF-04):
     - After successful `client.connect()`, store capabilities: `self._capabilities = client.capabilities`
     - If connect fails or times out, set `self._capabilities = {}` (empty dict -- entities will use defaults)
     - Return logic unchanged: `True` if connected, `None` if timeout/error, `False` never actually returned by current connect() logic (connect just returns False on auth fail, but _cgi_login swallows it). Keep the same tri-state logic.

  8. **__init__** -- Add `self._device_id: str = ""` and `self._capabilities: dict = {}` alongside existing `self._discovered` and `self._host`.

  **Critical implementation details:**
  - `CONF_CAPABILITIES` data in config_entry.data is a plain dict (JSON-serializable). HA persists it in `.storage/core.config_entries`.
  - Password validation uses the existing `_verify_pppp_login` which calls `client.connect()` -- this internally calls `_cgi_login(check_user.cgi)` which populates `client.capabilities`.
  - The `_do_pppp_check` static method should be updated to return `False` when `client.connected` is False after `connect()` returns True (edge case: connect succeeded at transport level but CGI login rejected).
  - Keep the 15-second timeout on PPPP check.
  - Do NOT remove the `check_rtsp` import -- it's still used in manual step when host is provided.
